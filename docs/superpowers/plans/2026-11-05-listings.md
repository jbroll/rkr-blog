# Listings and Collections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macro list slot fills from tagged pages, pages carry an `order`, and a tag with a matching published page becomes a collection with nested URLs and back/prev/next links.

**Architecture:** A pure pass, `resolveTagSources`, replaces tag-source slots in a page tree with rows looked up from the index before the existing figure prepass and `renderBlockTree` run, so the renderer never sees the db. `src/lib/collections.ts` owns collection membership, canonical paths and the nav. The index gains `excerpt`, `sort_order`, `image` and `post_tags.position`. One `cards` seed replaces three retired seeds.

**Tech Stack:** TypeScript (strip-types), Fastify, `node:sqlite` `DatabaseSync` via `Db` (`src/lib/db.ts:27`), `node:test` with `node:assert/strict`, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-11-05-listings-design.md`

**Model:** `opus`. Route precedence and redirect semantics interact with home-page, legacy and admin rules.

**Interfaces:**
- Consumes: `post_tags.position` (Task 1).
- Produces (`src/lib/collections.ts`):
  ```ts
  export const NON_COLLECTION_SLUGS: ReadonlySet<string>;
  export interface PageLink { path: string; title: string }
  export interface CollectionNav { back: PageLink; prev: PageLink | null; next: PageLink | null }
  export function collectionOf(db: Db, slug: string): { slug: string; title: string } | null;
  export function pagePath(db: Db, slug: string): string;            // '/<c>/<slug>' or '/<slug>'
  export function collectionNav(db: Db, slug: string): CollectionNav | null;
  export function memberExclusionSql(postAlias: string): string;      // SQL boolean: alias row is NOT a collection member
  ```
  `collectionOf` takes the page's tags by `position` and returns the first whose lowercased name equals the slug of a published `kind='page'` row. That slug must not be in `NON_COLLECTION_SLUGS` and must not be the page's own slug. Members for the nav are the published rows whose `collectionOf` is the same collection, ordered by `sort_order` (nulls last), then title. The nav renders for a draft member at that member's own sort position.
- Produces (`renderPostPage` data in `src/templates/post.ts`): an optional `collectionNav?: CollectionNav`. The markup is exactly:
  ```html
  <nav class="rkr-collection-nav"><a class="rkr-collection-back" href="/c">Back to Title</a><a class="rkr-collection-prev" rel="prev" href="…">Prev title</a><a class="rkr-collection-next" rel="next" href="…">Next title</a></nav>
  ```
  A null end omits its `<a>`. Text and attributes are escaped with the existing `escapeText` and `escapeAttr`.

**Interfaces:**
- Produces (`src/lib/tag-source.ts`):
  ```ts
  export interface TagSource { tag: string; sort?: 'order' | 'date'; limit?: number }
  export function isTagSource(v: unknown): v is TagSource;          // non-array object with a string `tag`
  export function tagSourceProblem(label: string, v: unknown): string | null;
  export type TagLookup = (src: TagSource, selfSlug: string | undefined) => Slots[];
  export function resolveTagSources(tree: BlockTree, lookup: TagLookup, selfSlug?: string): BlockTree;
  ```
  - `resolveTagSources` replaces every page-level macro instance slot value that `isTagSource` matches with `lookup(value, selfSlug)`. It descends grids. It does not look inside macro definitions. A value that fails `tagSourceProblem` becomes `[]`.
  - `tagSourceProblem` messages:
    - ``${label}: tag must be a non-empty string.``
    - ``${label}: sort must be order or date.``
    - ``${label}: limit must be a positive whole number.``
    - ``${label}: unknown key ${k}.``
- Produces (`src/lib/listings.ts`):
  - `export function listTaggedRows(db: Db, src: TagSource, selfSlug?: string): Slots[]`. Each row is `{ title, text, href, image, date }`, with `text`, `image` and `date` empty strings when null, and `href` from `pagePath`. It returns published rows of either kind with the tag (`COLLATE NOCASE`), excluding `selfSlug`. `sort:'order'` (the default) uses `sort_order` nulls last, then title. `sort:'date'` uses `published_at` desc, then title. `limit` applies `LIMIT`.
- Produces: `BlockRenderDeps` gains `lookup?: TagLookup; selfSlug?: string`. `prepareBlockRender` resolves the tree first and returns the resolved tree, so the prepass and render see rows. `renderEditBody(siteRoot, tree, log, campaign, lookup?, selfSlug?)`.
