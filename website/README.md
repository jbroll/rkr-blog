# rkr-blog marketing website

Static landing page for rkr-blog, served at `rkr-blog-www.rkroll.com`. Part
of the rkroll family of sibling sites (`checklist`, `drop-notes`,
`wicketmap`). The blog application itself is a separate deploy
(`../deploy.conf`, `roll-along.rkroll.com`) and is not affected by anything
here.

## Contents

Only `public/` is deployed to the web root; everything else stays private.

- `public/index.html` — landing page (hero + eight-card feature grid),
  hand-authored
- `public/about.html` / `public/privacy.html` / `public/terms.html` —
  generated by `build-legal.js`; do not edit by hand
- `public/rkr-blog-icon.svg` — nav logo / favicon
- `about.md` / `privacy.md` / `terms.md` — legal page **sources**; edit
  these, then regenerate
- `build-legal.js` — markdown → HTML generator (writes into `public/`)
- `deploy.conf` — static-mode Apache deploy config (kept out of the web root)

## Design

- Tailwind loads from its CDN, so there is no build step or bundler; the
  pages are plain files.
- The palette is the shared rkroll-family canvas, ink and line colours
  with a per-site accent, fuchsia `#c026d3`, set once in the `:root`
  block each page carries. Light only.
- The legal pages follow the sibling sites: markdown compiled by `marked`
  into the same nav and footer chrome as `index.html`, with
  `{{brand.name}}`, `{{brand.supportEmail}}` and `{{brand.websiteUrl}}`
  substituted. `marked` is a root devDependency and `build-legal.js` is a
  knip entry, so the gate counts both as used. `privacy.md` states what
  the app does with data: reader comments are stored, authors sign in
  with Google, the owner gets comment email, and an optional LLM reads
  comment text for spam filtering.
- No link to the app. The app has no public sign-up flow, so nav, hero
  and footer carry no call to action (`docs/DEFERRED.md`).

## Editing legal pages

```bash
# 1. edit the markdown source (about.md / privacy.md / terms.md)
# 2. regenerate the HTML:
node website/build-legal.js
```

## Preview

```bash
open website/public/index.html       # or: xdg-open website/public/index.html
```

## Deploy

```bash
deploy.sh init   website/     # first time: SSL cert + Apache vhost
deploy.sh update website/     # subsequent: copy static files
```

DNS for `rkr-blog-www.rkroll.com` must resolve to the VPS before `init`.
`deploy.conf` sets `APACHE_SPA_MODE="no"`: with SPA mode on, Apache
rewrites every missing path to `index.html` with a 200, so a request for
`/deploy.conf` would serve the homepage instead of a 404.
